# Retraining Strategy

## When to use
Use this skill when the task materially involves retraining strategy.

## Procedure
1. Inspect the repository, inputs, constraints, and existing conventions.
2. Define the expected outcome and how it will be verified.
3. Break the work into small, traceable steps.
4. Execute only the steps within the assigned scope and permissions.
5. Validate results with appropriate evidence, tests, or measurements.
6. Document assumptions, limitations, and follow-up risks.

## Quality checklist
- [ ] Requirements and constraints are explicit.
- [ ] Relevant edge cases are considered.
- [ ] Changes follow existing project conventions.
- [ ] Validation is reproducible.
- [ ] Results and unresolved issues are reported honestly.
